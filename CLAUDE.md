# video-factory: how to work in this repo

The main session is always the orchestrator: it talks to the user (in the user's language, plain words), owns the gates, the voice credits, the registration of scenes, the render and every git push. Agents do bounded work in parallel and report back; they never talk to the user, never spend credits on their own, never push.

Three things always wait for the user: the pick of a brief, the cost of a voice (said before it is spent), and the yes before anything is scheduled or published.

## Starting empty
A fresh copy of this repo holds the engine and the method, and none of the content: one neutral template host, one demo episode, the project's own presentation episode with its look (`video-factory`, the project's brand, not the user's), no series, placeholder settings. At session start, before any production, check what is still a placeholder:
- `brands/brands.json`: only the example brand `my-brand`, or a brand whose scheduler id or handles are empty (`null`) or `REPLACE_ME` and whose status is still `pending`;
- `looks/`: only `_TEMPLATE.json` and the project's own `video-factory.json` (no look of the user's yet);
- `src/layers/characters/`: only the template `Host.tsx` (no character of the user's own);
- `voices/catalog.json`: `voice_id` is `REPLACE_ME` (status `placeholder`); `characters/voices.json` points only at such a voice;
- `ideas/backlog.md`: only the example row; `series/`: only `_BIBLE_TEMPLATE.md`; `brands/shelves.json`: only the example shelf; `stats/`: no published video recorded.

Say what is missing in one or two lines, then propose to create what the requested video needs, one thing at a time, each as a suggestion the user can accept, change or skip ("there is no look yet: I suggest one built like this", then the preview). Order: the look (`docs/LOOKS.md`, `docs/STYLES.md`), then the host if the format wants one (`characters/README.md`), then the voice (heard by the user before it is used), then the brand and its connectors only when the user wants to publish (`docs/CONNECTORS.md`, `docs/PUBLISH.md`). Nothing is needed to try the engine: the demo episode `ep-000-demo` renders with the placeholder voice and the engine defaults. Never fill a placeholder with an invented id, handle or voice.

## Connectors (`docs/CONNECTORS.md`)
The factory uses three outside services: a voice service (built with ElevenLabs), a scheduling and analytics service (built with Metricool) and file hosting (a cloud drive). They are reached through whatever connector the session has: a direct connector or a hub that holds several apps. `docs/CONNECTORS.md` is the user's table of accounts: every call names its account when a service has several, and the scheduler connection is the one of the episode's brand (`connectors.scheduler` of the brand in `brands/brands.json`), never a default. A master is sent to the drive with the upload procedure of `docs/CONNECTORS.md` and `tools/drive_put.sh`. Read the voice credits left before a voice. Never add or remove a connection unasked. When a connector is missing, say which step it blocks and go on with what does not need it.

## Retention first
`docs/RETENTION.md` applies to every format and every new episode, before the format sheet: frame 0 states the subject, funny and with impact (absurd image + the whole hook sentence, `opening` in plan.json), nothing comes before the hook, the promise is complete by 3 s, the video is as short as the idea allows, the end loops, the cover is the opening frame, and every published video is measured with `tools/stats.py`. `tools/lint_plan.py` refuses a new episode that breaks the mechanical part of these rules.

## Follow call and shelves (`docs/RETENTION.md` §4 and §5, `docs/SHELVES.md`)
The hook is a spoken question the video answers. Every new episode asks for the follow at one third and at the end with a sentence that changes each time; the promise in it is the brand's true one and follows the brand's `weekly_target`. The end line sends the viewer to ONE place that exists (the next part, the saga, another episode, a link in the bio). Every episode sits on a shelf (`brands/shelves.json`): its cover carries the shelf band (`python3 tools/cover.py <id>`), the caption of a saga part starts with the shelf tag, and the cover is set on both networks. A new saga or a new kind of episode gets its shelf (label, colour, hashtag) at the brief.

## Language (`docs/LANGUAGE.md`)
One language per video, chosen at the brief: `python3 tools/new_episode.py <id> --lang en` writes `"lang"` in plan.json (`python3 tools/lang.py <episode_dir>` says which language and why: plan, else the saga's `series/<slug>/lang.json`, else the brand's `lang`, else the default of `tools/lang.py`). A saga speaks one language. Everything follows it: script, captions, hook card, HUD labels and every word drawn in a scene, the reference timing voice, the word lists of the lint and of the acting, the number format (`fmtNum(n, decimals, tk.lang)`, never a literal locale), the caption and hashtags, the `lang` column of the catalog. A voice the user has not heard in a language is sent to them before the render. Each language is written directly, never translated from a script in another one. Talking to the user stays in the user's language whatever the video's language.

## Formats
Every episode has ONE format from `formats/` (`python3 tools/formats.py` lists them). Read `formats/<id>.md` before writing anything: it rules tone, structure, look, sound, gates. `formats/modifiers/series.md` adds multi-part rules to any format. New format = copy `formats/_TEMPLATE.md` + a `.json`, fill, run `tools/formats.py`; no engine change is needed unless it needs a new layout.
The look (colours, set, fonts, kit style) is separate from the format: `looks/<id>.json`, chosen per series (`series/<slug>/look.json`) or per episode (`plan.json` `look`), see `docs/LOOKS.md`. A new saga gets its look at the brief: show `python3 tools/looks.py preview <id>` (an existing look, or a new one built from the references) with the 3 briefs. When `looks/` is empty, propose 2 or 3 directions and build one (`docs/LOOKS.md`).
Voices: `python3 tools/voice.py <episode_dir>` says which voice speaks and why. A host character always keeps his own voice (`characters/voices.json`); a hostless episode takes the narrator of its format; a saga can fix one voice (`series/<slug>/voice.json`); `plan.json` `tts` overrides for one episode and `voices` adds speakers for a dialogue. Voices live in `voices/catalog.json` with a status: a voice the user has not heard yet is generated once, they listen, then its status is updated. Never change the voice of a host or of a running saga without asking.
Every format accepts a host: an existing character or one created in the session (`characters/README.md`). `"character": "none"` gives the hostless layout.

## Phases (→ = waits for the user, ∥ = in parallel)
0. **Discovery**: pick the format (ask in one line if unclear). ∥ `reference-scout` writes `episodes/<id>/references.md` (references, angles, visual direction, useful skills and connectors, risks). The orchestrator checks which connectors and skills are really connected and loads the useful ones.
1. **Brief** → 3 briefs built on the references. Each brief IS its first second: the hook sentence (max 9 words, already funny or startling), the frame-0 image that collides with it, then one line of plot, format, length (series arc if any). The facts of the hook are checked before the brief is shown. The user picks.
2. **Script**: `tools/new_episode.py <id> --format <fmt>`; write script.md + plan.json. ∥ `fact-checker` and `script-critic` on the draft; apply; `tools/lint_plan.py`. → The user validates text, plan, close-ups/pauses (and the asset list for a montage).
3. **Production**: first the orchestrator fixes the art direction ALONE, before any builder starts: `episodes/<id>/style.md` (10 lines: the one world of the episode, the object followed and its accent colour, light direction, camera idea, what stays on screen all episode, the signature transition, one line per chapter saying what is seen) and `src/layers/scenes/<EpNNN>_shared.tsx` (the recurring subject, props and witness drawn ONCE as components, plus shared constants). Then ∥ one `scene-builder` per chapter (own file each; they import the shared file and never edit it; kit parts first) or `asset-scout` for a montage, WHILE the orchestrator runs build_episode (reference timing) and, after the user's go for the voice, the voice, alignment and post-alignment chain. The orchestrator then runs `python3 tools/gen_scenes.py`, which registers every scene file (no hand-edited registry).
4. **Check**: `tools/check.sh <id>` (scenes, plan, timing, sound); ∥ `qa-stills` (independent eyes on `tools/stills.py`); fix; `tools/render.sh <id> draft` for 15 s when the engine or a scene changed.
5. **Render and master**: `tools/render.sh <id> final`, `tools/master.sh`, contact sheet, `tools/sound_check.py episodes/<id> --master out/<id>.master.mp4`. → The user judges by ear and eye, with the sound numbers in front of them.
6. **Close**: `python3 tools/cover.py <id>` for the cover; after publication record the numbers with `python3 tools/stats.py add <id> ...` (read them in the analytics service yourself at about 24 h and 7 days, `docs/PUBLISH.md`; ask the user for an analytics screenshot only for what the service does not return), read the scoreboard, add notes to the format sheet's "Lessons learned" (and the series bible "State"), commit, push. As soon as a post is out, record its link (`python3 tools/catalog.py link <id> --instagram URL --tiktok URL`, then `catalog.py build`) so the catalog knows which episode, character and format it is. Once the 7-day numbers are in and the user asked no more change, `python3 tools/prune_audio.py <id> --apply` removes the intermediate audio (the render files and the voice takes stay).

After an engine change, `bash tools/selftest.sh` rebuilds and checks the demo episode `ep-000-demo`.

## Express mode
When the user gives a theme and wants it fast ("make me a video about X"): phase 0 runs as usual, then ONE message with the 3 briefs. The pick is the only stop before the finished video: it is also the go for the script and for the voice credits (say the credit cost in one line when the voice starts). The script, the plan and the list of close-ups are sent for information while production goes on; the user can stop or correct at any time, and a correction is applied before the next step. Fact-checker, script-critic and qa-stills still run, and an ERROR from one of them is fixed before going on. At the end the user receives the video, the caption and the slot chosen for them, with one question: "shall I schedule it for <slot>?". Nothing is scheduled or published without that yes.
The slot is studied, not guessed: the best-time data of the scheduler for each network of the brand (`getBestTimeToPostByNetwork` in Metricool), the hours of the brand's own best videos (`python3 tools/stats.py`), no other post of the brand within 20 h, and the earliest slot that fits, at least 3 h ahead. Say in one line why this slot.

## Rhythm and subjects
Each brand has a `weekly_target` in `brands/brands.json` (videos posted per week, set by the user; `null` = not set yet, ask once). At session start, after the numbers: count what the brand has published and scheduled for the current week (Monday to Sunday, in the brand's `timezone`) against the target and say it in one line ("2 of 3 this week, 1 missing"). When the week is not covered, propose subjects from `ideas/backlog.md` (verify the fact of an idea before showing it) and offer express mode. Keep the backlog at 5 ideas or more per active character: add to it from reference-scout reports, from what the numbers show works, and from the user's own ideas.

## Brands
An episode is published on ONE brand (one scheduler brand = one Instagram + one TikTok account). The registry is `brands/brands.json`; `python3 tools/brands.py` lists the brands and `python3 tools/brands.py of <episode_id>` says which one an episode belongs to (`brand` in plan.json, else `series/<slug>/brand.json`, else the default brand). Never write a scheduler brand id or a handle anywhere else. Before scheduling, the id and both handles of the resolved brand must match what the scheduler returns (`getBrandSettings`), and its status must be `active`; when they do not, or when they are still placeholders, stop and tell the user. A new brand gets its own entry (and usually its own look, host and voice); it never borrows the handles of another.

## Sound (`docs/SOUND.md`)
Nobody in a session can hear, so sounds are chosen and mixes accepted on measurements. Effects come from the sound library (`sounds/library.json`, files committed) through a kit (`plan.json` `"sound_kit"`, written by `tools/new_episode.py`).
- A gag or an object that needs its own sound (flush, glass, animal, machine): add it to the library BEFORE the voice, `python3 tools/sound_lib.py find <id> "<plain English description>"` (real recording through Openverse) or `pick` / `bank` (synthesized, earshot bank), then name it in `sfx_events` (`"kind": "<id>"`). A sound that does not score `strong` is not used; an effect nobody recognises is worse than none.
- `tools/check.sh` runs `tools/sound_check.py` (it installs earshot by itself, about 1 min): fix its ERRORs, act on its WARNs or say why not. After the master: `python3 tools/sound_check.py episodes/<id> --master out/<id>.master.mp4`.
- With the video, tell the user the result in two plain lines (effects on time or not, music level under the voice, master loudness) and ask them to judge by ear only what a measurement cannot: taste.
- Credits: when `sound_check.py` says credits are owed, `python3 tools/sound_lib.py credits episodes/<id>` gives the lines to add to the caption before scheduling.
- A host that refuses a download (403) is reported to the user with its name; never route around it.
- Commit `sounds/`, `sfx_cues.json` and `sound_report.json` with the episode.

## Parallel work rules
- One writer per file. Scene builders write `src/layers/scenes/<EpNNN>_<chapter>.tsx` only (the orchestrator owns `<EpNNN>_shared.tsx` and `style.md`; a builder who needs a new shared part asks for it in its report); shared files (Scene.tsx, Episode.tsx, types.ts, tools) are edited by the orchestrator, or by one agent at a time.
- Renders are heavy: on a small machine (2 cores) agents render stills one at a time and never a video; only the orchestrator runs a full render, and nothing else renders meanwhile. `VF_CONCURRENCY` sets the render concurrency.
- Checks that judge work (facts, script, stills) go to an agent that did not produce it.
- Agent briefs name: the files to read, the one file to write, what "done" looks like, what to report.
- An agent spends credits, uploads or schedules only on a written order of the orchestrator that carries the exact account, voice, cost, brand id, slot, caption and file ids, never on its own initiative.
- If an agent type of `.claude/agents/` is not offered by the session, start a general-purpose agent with that file's text as its brief.

## Code
English only, comments included. New scenes take colours, stroke widths and radii from `kit(preset)` / `preset`, never as literals, so they follow the look. Reusable drawing parts live in `src/kit/` (`docs/KIT.md`); a part drawn twice in episodes moves to the kit. plan.json / episode.json fields: `docs/ENGINE_CONTRACT.md` and README.md. Machine settings come from the environment (`VF_CHROME`, `VF_CONCURRENCY`), never from a path written in the code. Never commit `node_modules`, `out`, `public/episodes`.
