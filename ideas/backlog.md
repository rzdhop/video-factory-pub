# Subject backlog

Ideas waiting for a brief, per character (or per kind of episode when there is no host). The orchestrator feeds this
file (reference-scout findings, what the numbers say works, the user's own ideas) and proposes from it whenever the
week's target is not covered (`brands/brands.json`, `weekly_target`). Keep 5 ideas or more per active character.

Status:
- `to check`: the fact behind the hook is not verified yet. Verify it before showing a brief; an idea never goes to
  the user as a brief while `to check`.
- `checked`: sourced, ready for a brief (name where the sources are).
- `planned`: belongs to a saga's arc (see its bible).
- `used: <episode id>`: produced.

Language (`docs/LANGUAGE.md`): an idea works in any language; its draft hook is written in the language it is planned
for, marked `[en]` or `[fr]` before the hook when the brand posts in two languages. Rewrite the hook, do not
translate it, when the language changes.
Technical ideas name the REAL term (mechanism, API, file, standard, identifier), never a vague stand-in
(`formats/tech-serieux.md`, "Real terms").

When this file holds only the example row, the backlog is empty: ask the user for their subjects, and add ideas
from the first reference-scout reports.
